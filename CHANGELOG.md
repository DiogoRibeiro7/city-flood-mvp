# Changelog

These entries are unreleased. Metadata is staged as Python `1.0.0rc1` and
web/API/citation `1.0.0-rc1`; no version tag, release or deposit is authorized by
this file. The [readiness review](docs/releases/v1-readiness.md) records the
go/no-go decision and exact verification evidence.

## Unreleased — preparing v1.0.0

### Added

- Demonstration acceptance gates and implementation/API audits.
- Disposable full-stack smoke with fixed synthetic input, worker/scheduler
  checks, exact CSV assertions, failure diagnostics and cleanup.
- Fresh and seeded Alembic verification, integrity checks and failure/retry guidance.
- Python 3.12–3.14 test matrix, separate static checks, retained failure
  artifacts, candidate checklist, version policy and evidence manifest.
- NOAA GHCNh source assessment and licensed fixture, bounded historical ingestion,
  replay/deduplication and provenance. Quality reports distinguish missing, trace
  and quantitative rain and characterize sampling and clipped interval support.
- Independent-event evaluation protocol and controlled scoring tests. The Porto
  2010 case study reproduces recorded rainfall ingestion, descriptive interval
  analytics, tables, figures and an observation timeline.
- Worker metrics, bounded-label telemetry, proposed SLI/SLO thresholds, Grafana
  panels and alert-rule tests. Disposable logical backup/restore, worker kill/retry,
  stale-job and corrupt-archive drills retain measured local results.
- Operator review of raw source/quality metadata and the producing analytics run,
  shared UTC windows, accessible measurement/comparison tables, linked notes,
  worker CSV downloads, browser regressions and scoped accessibility checks.
- Citation metadata grounded in repository authorship, a reproducibility statement
  and a tagged-release checklist. No DOI, ORCID, affiliation or release date is invented.

### Fixed

- API validation serialization, mixed-timezone job bounds, and schema statuses
  inconsistent with runtime HTTP 400 responses.
- Scheduler JSON city extraction and ORM defaults that froze timestamps at
  table creation instead of evaluating them on insertion.
- Formatting baseline so CI can enforce the locked Ruff formatter.
- Removed tracked generated bytecode so matrix tests do not dirty the source checkout.
- Deployed data-read admission and dedicated-tenant enforcement, credential/cache
  handling, stale UI responses and empty map-filter selections. The deployment
  remains limited to one API process/replica for process-local quotas.
- Smoke database readiness now requires TCP availability instead of accepting the
  temporary Unix-socket bootstrap server. Browser JUnit paths match CI retention.

### Changed

- Web CI/container use Node 24; dependency tooling versions are aligned.
- Required stack checks use the disposable runner. The operator browser flow uses
  actual API/database/worker services; retained synthetic screenshots identify the
  tested implementation commit and supplement assertions.
- Actions use verified commit pins and explicit read-only content permissions.
- Package description and author metadata now describe the implemented software
  and replace the placeholder author with the repository's established contributor.
- In non-local deployments, formerly public data reads require authorized
  credentials and dedicated-tenant configuration. Successful payloads and `/v1`
  paths remain compatible; see the [security migration notes](docs/releases/security-review.md).

### Known limitations

- Synthetic scenarios and descriptive recorded rainfall are separate evidence.
  Independent flood-event labels are absent; six-hour means cannot validate the
  15-minute detector. Accuracy, calibrated flood probability and lead time are not established.
- Legacy timestamp nullability, optional Timescale policies, CSV/auth schema
  gaps and pagination ties remain tracked in the acceptance gates.
- Dependency audit findings require remediation and retesting. Shared-database
  tenancy, multiple API processes, operational SLO attainment and municipal
  production readiness remain unsupported.
- See the [v1 readiness review](docs/releases/v1-readiness.md) and
  [publication checklist](docs/releases/v1-release-checklist.md) before any release decision.
